Reviewer checklist

Use this when reviewing a change. Each item is an invariant the design depends on, where it lives in the code, and the test that proves it. Ticks are saved in this browser only.

Invariants

  • A file is in exactly one place. Source → staging only by os.rename on the same drive; staging → gone only after verify + index. No copy+delete, no overwrite.
    stage, finish_staged · test_full_flow_then_append, test_crash_after_staging_is_resumed
  • Listed before moved. Manifest lines are flushed and fsync'ed before their files are renamed.
    stage · test_crash_after_staging_is_resumed
  • Verify before delete. Staged copies are deleted only after: every staged BLAKE3 equals the head's content_hash, mochi verify --level content passes, and the SQLite transaction committed.
    commit_month, finish_staged · test_failed_commit_keeps_staging
  • No duplicate commit on resume. Resume compares the head with the staged hashes before committing.
    commit_month(resume=True) · test_crash_after_commit_before_index_makes_no_new_commit
  • Indexing is repeatable. scanned_log_entry is upserted on (relative_path, file_storage_volume_id); session_barcode is INSERT OR IGNORE.
    index_month, _run_with_index
  • Months are independent. A failed month keeps its staging; others finish; the run then raises.
    finish_staged
  • Unknown files are kept. Anything in staging not in the manifest is reported, never deleted.
    finish_staged
  • One run at a time. OS lock on .backup.lock for the whole run (and export).
    lock_run · test_second_run_at_the_same_time_is_refused
  • Engine checked before anything moves. A real run without a working mochi stops before staging.
    _run → check_mochi · test_missing_mochi_moves_nothing
  • Cancel leaves no trace. confirm → False: nothing moved, no session row.
    test_callbacks_report_steps_and_cancel_moves_nothing
  • Threads never touch SQLite or delete files. Workers only hash and run mochi; the main thread indexes and deletes.
    commit_month vs finish_staged
  • Only exit 0 and 2 pass. Any other mochi exit raises. Arguments are a list, never a shell string.
    mochi()
  • Resources are closed. The index connection is closed in finally; the lock file is closed by with. (On Windows an open connection locks index.db.)
    _run, open_index
  • The UI makes no backup decisions. backup_ui.py only calls run, export, check_mochi, check_sql, send_email.
    UI ↔ logic
  • SQL Server is read only and parameterised. No writes; dates as %s parameters.
    query_candidates
  • The password is never written. Asked at run time or from DB_PASSWORD; removed from the exported config.
    backup_ui.main, export · test_export_copies_checked_and_skips_unchanged

Red flags in a diff

If you see…Ask…
shutil.move, shutil.copy + unlink in the staging pathCan the file end up in two places, or none, after a crash? Does it still work across drives without silently copying?
A new unlink / rmtree / rmdirIs the file archived, verified and indexed first? Is it listed in the manifest?
Code moved from finish_staged into commit_monthDoes it now run on a worker thread? Does it touch SQLite or delete?
returncode checks changed, or shell=TrueDoes a MOCHI failure still stop the month? Can a path be misread by a shell?
A new field read from MOCHI's JSONIs it in MOCHI's documented output (docs/c14-cli.md) for the version in use? What if it is missing?
sqlite3.connect without a matching closeWho closes it, on every path, including errors?
File or database code in backup_ui.pyShould this live in logs_backup.py, with a test?
A test that is skipped, removed, or no longer needs mochiWhat does the Flow suite still prove? Check the skipped count.
String-built SQL (f"… WHERE x = '{v}'")Use parameters. (The only f-string SQL today builds the WHERE from fixed text, with values still as parameters.)

Validate a build by hand

After the automated tests, on a test PC with a copy of real data:

  1. FinisarLogsBackup.exe --check-sql → both panels green: mochi: found with the version and path, SQL Server: connected.
  2. FinisarLogsBackup.exe --dry-run → the plan per month; compare a few barcodes with SQL Server and the folders by eye.
  3. A real run on a small date_range; answer y.
  4. Pick one archived file and check it end to end: 
    sqlite3 E:/archive/index.db "SELECT relative_path, content_hash FROM scanned_log_entry WHERE barcode='BC001'"
mochi get E:/archive/2026/2026-08.mochi BURNIN/unit1_BC001_log.txt -C D:/restore
b3sum D:/restore/BURNIN/unit1_BC001_log.txt      # must equal content_hash
  5. mochi verify E:/archive/2026/2026-08.mochi → exit 0 or 2.
  6. Pull the plug test (optional): start a run on a bigger window, kill the process during "Commit, verify, index", run again. The summary shows Resumed N files; mochi list shows no duplicate commit for the month.

Questions reviewers ask

Why Python plus a Rust program, not all one language?

MOCHI is a large, separately specified and tested archiver. This tool only needs to decide which files go where and keep a ledger; that is short, readable Python. The command line is a stable, documented contract between them. See Python ↔ MOCHI.

Why is a run "LOCAL_COMMITTED" and not "backed up"?

Because the archive is one file on one disk. A disk failure loses it. --export to another drive makes the independent copy; the UI says so after every run.

Why does every Windows commit say DEGRADED?

After publishing, MOCHI flushes the folder entry, but Windows does not document that flush as durable, so MOCHI reports directory_unconfirmed with exit 2. The data is committed; Python logs it as "not an error" and continues to verify.

Why verify the whole month each run, not only the new commit?

Simplicity and coverage: mochi verify --level content checks the archive as a whole. It makes appends to big months a few seconds slower (docs/performance.md).

Why is staging on the source drive and not the output drive?

A rename is atomic only within one drive. Moving to the output drive would be a copy plus a delete, which a crash can interrupt in between.

What happens if two barcodes are in one file name?

The file is left in place and counted as an error: it is not clear which month it belongs to. A person decides.
