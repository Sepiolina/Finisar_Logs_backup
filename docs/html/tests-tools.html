Tests, build & tools

test_logs_backup.py, build_exe.bat, run_backup.bat, bench.py, config.example.json and requirements.txt: what each does and how they fit together.

test_logs_backup.py

21 tests in three groups, using Python's built-in unittest. Run them with:

MOCHI_BIN=/path/to/mochi python -m unittest -v test_logs_backup

Matching 2

Pure functions: the barcode and extension rules. No disk.

ConfigFile 7

Config, SQL error text, encryption, finding config.json, the registry, the index folder. Temp folders only.

Flow 12

Full runs with the real mochi on real temp folders. Skipped when mochi is not found.

How the tests reach the Rust engine

At the top: MOCHI = os.environ.get("MOCHI_BIN") or shutil.which("mochi"). If neither gives a path, the whole Flow class is skipped (@unittest.skipUnless(MOCHI, …)) and the run says skipped=12. So "all tests pass" without mochi proves much less: check the skipped count. build_exe.bat prints a reminder about MOCHI_BIN when tests fail.

Patterns used
  • No mocks of MOCHI. Flow tests run the real binary, so they catch contract changes between the two repos (a renamed JSON field, a new exit code).
  • SQL Server is replaced, not mocked: lb.run(cfg, lambda *_: self.CANDIDATES) passes a fixed list through the candidates_fn door.
  • Crash = calling the inner steps by hand. A "crash after staging" test calls scan and stage itself, stops, then calls run as the next run would.
  • Every resource is released with addCleanup: temp folders, SQLite connections (Windows locks open files), the logger level.
  • Temp folders are .resolve()d, because Windows may hand out short 8.3 names (IT_113~1) while the code reports long ones.

Every test, and what it proves

test_barcode_needs_delimiters_on_both_sides Matching

é123ü no; é_123-ü yes; 123_12345 finds both; x12345 no; AB-7 containing a delimiter still matches. Non-ASCII letters are not delimiters.

test_extension Matching

a.b.TXT yes (last part, any case); noext no; a.txt.bak no.

test_sql_login_from_config_with_env_override Config

DB_USER and DB_PASSWORD win over the file; an empty login names every missing part.

test_backspace_in_a_path_is_refused Config

"E:\backup.db" in JSON contains a backspace; the config is refused with a message about /.

test_sql_errors_are_one_readable_line_with_a_hint Config

Real pymssql error shapes (20002 handshake, a stale 18456 code with a 20009 text, a login failure) become one line with the right hint; an unknown encryption value is refused.

test_encryption_values Config

Nine spellings map to request/off/require in the written freetds.conf; the "without encryption" warning is checked (not printed) for off.

test_config_is_found_without_an_argument Config

Current folder first, then next to the program, a given path always wins, and in a frozen .exe "next to the program" is the .exe's folder.

test_mochi_path_from_the_registry Config

A fake registry: App Paths first, install key + bin second, nothing when empty, nothing off Windows; registry places come before PATH; a configured path is the only place.

test_index_folder_is_created Config

open_index creates missing folders for db_path.

test_full_flow_then_append Flow

The example run: 2 files archived into 2 months, BC404 unmatched, non-matching files untouched, staging gone, index rows with the archive's BLAKE3 and commit_seq 0, user_version 2. Then a late file: the second run makes commit 1 and the head shows both files.

test_crash_after_staging_is_resumed Flow

Stage by hand, stop, run again with no candidates: the leftover batch is still archived and staging removed.

test_crash_after_commit_before_index_makes_no_new_commit Flow

Stage and commit by hand, stop before indexing: the next run leaves the head at seq 0 (no duplicate commit) and indexes both files.

test_callbacks_report_steps_and_cancel_moves_nothing Flow

confirm returns False: status cancelled, the plan's numbers are right, only query/scan reported, files untouched, no session row. Then True: 2 files moved and commit reported.

test_second_run_at_the_same_time_is_refused Flow

While the lock is held, run raises "another backup run" and moves nothing; afterwards it works.

test_export_copies_checked_and_skips_unchanged Flow

Export copies 2 archives and the index with matching BLAKE3, removes the SQL password, writes RESTORE.txt; a second export copies nothing; a target inside output_dir is refused.

test_mochi_is_found_without_a_config_path Flow

With the registry switched off and PATH empty: not found (error lists the checkout path, no desktop hint); then found in a MOCHI/target/release checkout, in ~/.cargo/bin, in the setup's bin; and the desktop-app hint when only mochi-desktop.exe exists.

test_recursive_scan_keeps_folders_and_appends_into_them Flow

Deep files keep their folders in the archive; the same file name in two folders stays two entries; a later file in an existing folder is added and the earlier one stays.

test_recursive_off_and_staging_inside_a_subfolder Flow

recursive: false scans only the top of each subfolder; a staging folder inside a subfolder is never scanned; a non-boolean recursive is refused.

test_missing_output_staging_and_index_folders_are_created Flow

New output, staging and index folders are created; an output path blocked by a file gives "cannot create output_dir".

test_missing_mochi_moves_nothing Flow

A bad mochi path stops a real run before anything is staged; a dry run only warns and still reports 2 matches.

test_failed_commit_keeps_staging Flow not on Windows

A fake mochi (a shell script) that answers --version but fails every commit with IO_ERROR: the run raises, files stay in staging; with the real mochi the next run finishes them. Skipped on Windows because it needs a shell script.

build_exe.bat

Builds dist\FinisarLogsBackup.exe, one file that runs on a Windows PC without Python. Each step stops the build on failure (|| goto :fail).

run_backup.bat

cd /d "%~dp0"                                  :: go to the .bat's own folder
if exist ".venv\Scripts\python.exe" ( ".venv\Scripts\python.exe" backup_ui.py %* ) else ( python backup_ui.py %* )
pause                                           :: keep the window open to read the summary

For running from source on Windows by double-click. %* passes any options through.

bench.py

python bench.py FILES MONTHS DIR [--append N] [--mochi PATH]

Generates FILES small logs (about 2 KiB each) over five subfolders and MONTHS months, runs one backup through lb.run with a fixed candidate list, and prints seconds per step. Its report callback records the time between progress calls, which is how it splits the run into steps without any timing code inside the logic. --append N then adds files and runs again (the daily case). It deletes DIR first. Results and tuning: docs/performance.md.

config.example.json and requirements.txt

config.example.json

Every setting with a safe example value; password and mochi are null (asked / searched). Copied next to the .exe by the build. Reference: config.json.

requirements.txt
