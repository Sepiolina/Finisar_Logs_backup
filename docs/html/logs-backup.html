logs_backup.py

All the backup logic, about 920 lines, laid out top to bottom in the order a run executes it and split by # ---- section comments. Each function below opens to show what it does, why, and what to watch when changing it.

Constants and schema

DELIMITERS, MANIFEST_BATCH, WORKERS, SCHEMA the knobs
DELIMITERS = "_.-"Characters allowed on each side of a barcode in a file name.
MANIFEST_BATCH = 2000Manifest lines synced per fsync before their files move. Bigger = fewer syncs. Safety does not depend on its value.
WORKERS = min(cpu_count, 8)Hashing threads, and how many months are committed side by side.
SCHEMA_VERSION = 2, SCHEMAThe four SQLite tables (described here), all CREATE … IF NOT EXISTS.
Why now() returns "epoch:1730000000" and not a date: the format is the one the earlier tool wrote, so both tools' indexes read the same.
BackupError, quiet(step, message, done, total) expected failures; the do-nothing progress callback

BackupError is raised for every expected problem (bad config, mochi missing, SQL login wrong, a month that failed). Its message is written for the operator. Anything else that is raised is a bug or an OS error.

quiet is the default report callback, so the logic can always call report(...) without checking whether a UI is attached.

Config

program_dir() the folder this program lives in

The .exe's folder when frozen by PyInstaller (sys.frozen), otherwise the folder of logs_backup.py.

In the .exe, __file__ points into a temporary unpack folder that disappears after the run. Looking for config.json or mochi.exe "next to the program" must use the real .exe location.
find_config(given=None) which config.json to use

The given path; else config.json in the current folder; else next to the program. Raises with both folders named if none exists. Test: test_config_is_found_without_an_argument.

class Config reads and checks config.json

Turns the JSON into attributes (source_dir, output_dir, staging_dir, db_path, subfolders, extensions, recursive, lookback_days, date_range, mochi, email, sql) with defaults. sql merges sql_server with DB_* environment variables (environment wins). Two helpers: cfg.manifest and cfg.archive(month) → output_dir/YYYY/YYYY-MM.mochi.

Refuses: a path with a control character (a JSON \b or \t from a Windows backslash), a subfolder that is not one plain folder name, a non-boolean recursive.

Validating up front means a typo stops the run before anything is touched, with a message that names the setting.
A subfolder like ../other would let the scan leave source_dir; the plain-name check prevents it. Keep it if you add settings that become paths.

SQLite index

open_index(path) / _check_index open or create index.db; caller must close it

Creates the folder, connects, checks user_version is 0 (new) or 2 and that no old-format columns exist, then runs the schema. On any failure after connecting, it closes the connection before raising.

On Windows an open SQLite connection locks the file: nothing can move or delete index.db until it is closed. Every caller closes it (_run in a finally; tests via addCleanup). with db: is a transaction, it does not close.
start_session(db, from, to)

Inserts a scan_session row with status running; returns its id.

complete_session(db, sid, status, barcodes, moved, errors)

Sets completed_at, the final status (success / failed) and totals.

query_window(db, cfg) which dates to ask SQL Server for

date_range if set. Otherwise: end = today (UTC) − lookback_days; start = last successful run's end − 1 day, or None on the first run. Sessions dated resumed are ignored.

The start comes from the index, not a fixed schedule, so a missed week is caught up automatically.

SQL Server

query_candidates(sql_login, from, to) SQL the one business query
SELECT DISTINCT sfs.serial_no, CONVERT(VARCHAR(50), sft.last_update, 120)
FROM ForthUtilities.dbo.ShipmentFinisarSerial sfs WITH (NOLOCK)
JOIN ForthUtilities.dbo.ShipmentFinisarTrace sft WITH (NOLOCK) ON sfs.trace_id = sft.trace_id
WHERE sft.last_update >= %s AND sft.last_update < %s

Dates are parameters (%s), never pasted into the text: no SQL injection, no date-format surprises. Barcodes are stripped of spaces. Returns [(barcode, "YYYY-MM-DD HH:MM:SS")].

WITH (NOLOCK) reads without taking locks, so the backup never blocks the production database. The price is a "dirty read": a row being written at that moment may be seen early or not at all. It is the same query the earlier tool ran; the 1-day window overlap gives a late row a second chance.
run_sql(sql_login, sql, params, retries) connect, run, retry with backoff

Imports pymssql only here (the rest of the module and the tests work without it). Names any missing login part. A HOST\NAME server connects by instance name with no port. Retries DB_RETRY_ATTEMPTS times (default 3) waiting 2 s, 4 s, 8 s…; the last failure becomes a BackupError via sql_error.

check_sql(sql_login)

SELECT @@VERSION with no retries, for --check-sql.

set_encryption(mode) login encryption through a tiny freetds.conf

Normalises null/true/false/"yes"/"0"… to request, require or off, writes [global] encryption = <mode> to a temp file and points FREETDSCONF at it. off logs a warning every run.

FreeTDS (the driver inside pymssql) reads this setting only from a config file, not from a connect argument.
sql_error(e), SQL_HINTS one readable line + a hint

pymssql errors are a code plus a multi-line byte string. This keeps the first meaningful line, takes the code from the text when it starts with DB-Lib error message N (pymssql can keep a stale code), and adds a hint for 20002 (handshake/port/encryption), 20009 (unreachable), 18456 (login), 4060 (database).

Scan

find_barcodes(name, barcodes) barcodes bounded by delimiters
starts = [0] + [i + 1 for i, c in enumerate(name) if c in DELIMITERS]
ends   = [i for i, c in enumerate(name) if c in DELIMITERS] + [len(name)]
return {name[s:e] for s in starts for e in ends if e > s and name[s:e] in barcodes}

Every substring that starts at a boundary and ends at a boundary, looked up in a set. Try it in the playground.

has_extension(name, extensions)

Text after the last ., lower-cased, must be in the set. No dot = no extension.

walk_files(top, recursive, skip, on_error) streaming folder walk

A loop with an explicit stack, using os.scandir: yields (folder below top, entry) for each file. Does not follow symlinks; does not enter folders in skip (staging and output); passes unreadable folders to on_error and goes on.

A generator never holds a whole huge folder tree in memory; an explicit stack avoids Python's recursion limit on deep trees. Skipping staging matters when staging_dir is inside a subfolder: otherwise a run would re-scan its own staged files.
scan(cfg, dates, report) → (entries, errors, scanned)

For each subfolder, each file: allowed extension, exactly one barcode, a valid YYYY-MM month from dates[barcode]. Builds manifest-ready dicts. Two or more barcodes = ambiguous, counted as an error and left in place. Reports progress every 2,000 files.

staged_path(cfg, entry)

staging_dir / volume_name / relative_path. The single definition of where a staged file lives.

Stage

stage(cfg, sid, entries, report) the most safety-critical function
  1. Refuses if staging and source are on different devices (st_dev): a rename cannot cross drives.
  2. Creates the target folders.
  3. Writes the header line, then per batch of 2,000: write lines → flush() → os.fsync() → rename each file.
  4. Never overwrites: an existing target raises FileExistsError for that file, which is logged and left in the source.
"Listed before moved" makes the manifest a complete list of staging. Renames run on one thread: measured, threads made them slower because they queue on the same folder.
Do not reorder the fsync and the rename, do not replace os.rename with a copy+delete, and do not add an overwrite: each would break "a file is in exactly one place".
read_manifest(cfg) → (session id, entries) or None

A broken header = nothing safe to resume (None). A broken line (only the last can be, after a crash) is skipped.

MOCHI

The full story of this section, with an interactive search order and real JSON, is on Python ↔ MOCHI.

registry_mochi(reg=None) Windows: where the MOCHI setup put mochi.exe

App Paths (HKCU, then HKLM), then the install-location key + bin\mochi.exe. [] off Windows. Tests pass a fake reg.

mochi_places(configured)

The configured path only, or: registry, PATH, %LOCALAPPDATA%/MOCHI/bin, ~/.cargo/bin, program folder, ../MOCHI/target/release, ../mochi/target/release. Order kept, repeats removed.

check_mochi(cfg) --version

Tries each place; the first that exits 0 and prints mochi … wins and cfg.mochi becomes its full path. Otherwise raises, listing every place and why it failed, plus a hint if only the desktop app is installed (desktop_app_hint).

mochi(cfg, *args) every command the only door to mochi.exe
p = subprocess.run([cfg.mochi, "--json", "--no-local-history", *map(str, args)],
                   capture_output=True, text=True)
out = json.loads(p.stdout)        # {} if not JSON
if p.returncode not in (0, 2):
    raise BackupError(f"mochi {args[0]} {args[1]}: exit {p.returncode} {out.get('error') or p.stderr.strip()}")
return out

If cfg.mochi is not yet an absolute path it calls check_mochi first. Arguments are a list, never one string through a shell, so paths with spaces or special characters cannot be misread.

head_files(cfg, archive) list

({path: content_hash}, (seq, commit_id)) for files in the head; ({}, None) if the archive does not exist.

b3(path), hash_all(pool, paths, chunk=500)

b3: BLAKE3 of a file through a memory map, with BLAKE3's own multithreading for large files. hash_all: submits chunks of 500 paths to the pool and returns a lazy iterator of hashes in order, so hashing runs while MOCHI commits.

commit(cfg, month) create / append

create if the archive file does not exist, else append, with every staging/<month>/<SUB> folder as input. Logs DEGRADED (not an error) when durability is not durable.

commit_month(cfg, month, entries, resume=False) commit + check one month; runs on a worker thread
  1. Start hashing every staged file.
  2. Normal: commit. Resume: list the head first; commit only if some staged file is missing or differs (prevents a duplicate commit after a crash).
  3. List the head; every staged path must have the same hash, else raise.
  4. mochi verify --level content.
  5. Return (hashes, (seq, commit_id)).
It must not touch SQLite or delete anything: it runs on a worker thread, and the main thread decides about deletion only after indexing. Keep it that way.

Index and clean up

index_month(db, cfg, sid, month, entries, hashes, head) one transaction

Inside with db: (commit or roll back as a whole): insert/update the month's file_storage_volume, upsert each scanned_log_entry (ON CONFLICT … DO UPDATE), recount entry_count.

An upsert makes re-indexing after a crash harmless: same rows, same values.
finish_staged(db, cfg, report, resume=False) archive what the manifest lists
  1. Read the manifest (none → return None). If its session is missing from the index, record into a new resumed session.
  2. Keep entries whose staged file exists; group by month.
  3. Submit commit_month per month to a pool.
  4. On the main thread, month by month: get the result → index_month → delete that month's staged files. A failure is logged; the month keeps its files; the others go on.
  5. If any month failed: raise, keep the manifest.
  6. Else: delete the manifest, remove empty folders, report (never delete) files not in the manifest, complete the session.

Run

lock_run(cfg) one run at a time

Creates output_dir, opens .backup.lock, takes a non-blocking exclusive OS lock (msvcrt.locking / fcntl.flock). Returns the open file; closing it (end of the with, or process death) releases the lock.

plan(entries)

{month: (barcodes, files, bytes)}, sorted. Used for the confirm question, the dry run and the summary.

run(cfg, candidates_fn, dry_run, report, confirm) the public entry point

Defaults candidates_fn to the SQL Server query, takes the lock, calls _run. Contract: UI ↔ logic.

prepare_folders(cfg)

Creates output, staging and the index folder (clear error naming the setting if it cannot). Warns, without creating it, if source_dir is missing.

_run(...)

check_mochi (fatal unless dry run) → prepare_folders (not in a dry run) → open_index → _run_with_index in try, db.close() in finally.

_run_with_index(db, ...) the run itself

Resume leftovers → window → query → scan → plan. Dry run: return. Confirm says no: return cancelled. Otherwise: start session, record new barcodes (skipping ones already recorded), stage, finish, complete. Any exception marks the session failed and re-raises.

Export and email

copy_checked(src, dst)

Copies through dst.partial, hashing while reading, fsync, re-hashes the copy, keeps the timestamps, then renames into place. A mismatch deletes the partial and raises.

export(cfg, target, report) an independent copy to restore from

Refuses a target inside (or containing) the source or output folder. Holds the run lock. Copies every archive and any staged file with copy_checked, skipping archives unchanged since the last export (size + mtime in export-manifest.json). Copies the index with SQLite's backup API (a consistent snapshot, unlike a file copy), writes config.json with the password removed, and RESTORE.txt.

send_email(cfg, summary)

Best effort: POSTs an HTML table to {api_base_url}/api/email/send; barcodes are HTML-escaped and the body is capped at 95,000 characters. A failure is a warning.

main() python logs_backup.py

Plain logging to the console, no questions: [config] [--dry-run] [--export DIR]. For scheduled tasks.
